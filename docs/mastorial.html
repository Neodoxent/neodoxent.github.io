I. Purpose

The Mastorial is the system's memory. It preserves the relation between architecture, doctrine, code behavior, symbolic grammar, mathematical readings, aesthetic semantics, and development direction. It exists to prevent the system from expanding into incoherence.

Core PurposeThe Mastorial makes the system legible to the future author, future collaborators, future audits, and future coding agents. Every meaningful interface change should be reflected here. The page is not only a guide to the website; it is a guide to the system beneath the website.

Its deeper function is governance. It slows development enough that additions can be judged against the whole. It should be dense enough for expert use, but readable enough that a returning architect can regain the project in one sitting.

II. System Definition

The Neodoxent Infotech Interface Layer is a state-driven, recursive, symbolic interface system designed to prepare readers for structured exposure to Ascendancy. It is a website, but it is not merely a website. It borrows from dashboards, ritual thresholds, symbolic cards, knowledge maps, incremental disclosure, and cybernetic feedback loops, but it should never reduce itself to any one of those forms.

Primary DefinitionThe system does not simply reveal content. It alters the interface according to the reader's interaction state until the reader has enough orientation, coherence, trace, and symbolic literacy to receive deeper content.
What It Is
A cognitive instrument, recursive interface architecture, semiotic access layer, progressive orientation console, symbolic state machine, and public-safe bridge into deeper books, artifacts, maps, glyphs, cards, and protocols.
What It Is Not
It is not a conventional game, therapy, diagnosis, empirical measurement, occult authority, ARG puzzle-box, or complete compression of Ascendancy into one page.
Interpretive BoundaryThe interface may feel meaningful because it is coherent, paced, and responsive. Coherence does not make arbitrary claims true. The system is an instrument of structured engagement, not an oracle.

III. Architecture Stack

The system is modular by necessity. Each file has a distinct function. This separation prevents the interface from becoming a monolith and allows future Codex or human audits to operate without destroying the shell.

recursion.html                 → Protected interface vessel / Meta-Landing chamber
assets/js/state-engine.js      → Core state, resources, qBits, strata, field math, unlock API
assets/js/modules.js           → Chamber doctrine, grants, requirements, segments, dwell gates
assets/js/main.js              → Rendering, binding, field log, resources, warnings, module display
assets/js/interface-drawer.js  → Drawer, field pill, mobile shell, accept reasons, contextual card layer
assets/js/manifest-calibration.js → Runtime calibration overlay for Manifest Seed, depth, complexity
docs/mastorial.html            → Master guide, doctrine, recovery manual, roadmap
Cybernetic Loop
User Action → State Update → Calibration → Render → Guidance → User Action

This loop is what makes the interface cybernetic. It does not merely host text. It observes interaction, transforms state, evaluates readiness, changes visibility, and returns guidance.

IV. Protected Shell Doctrine

recursion.html is the sacred vessel of the system. It has already broken twice from placeholder replacement. That failure mode is now doctrinally known and must not be repeated.

Never Again RuleNever replace recursion.html wholesale unless a complete verified copy is being restored. Do not use placeholder comments such as body unchanged or styles omitted. The page will become blank.
Safe changes:
- append a script tag carefully
- patch a small known section
- restore from a complete known-good file

Unsafe changes:
- rewrite entire shell casually
- use placeholder body or placeholder CSS
- combine feature work with shell recovery

VII. Field Mathematics

The field mathematics exist to keep the interface lawful. The numbers are symbolic and functional. They are not empirical measurements. Their role is to govern pacing, reveal, readiness, and feedback.

Foundation
Foundation ≈ attention + orientation + witness + orientation strata + stabilization strata

Foundation rises early. Zephyr should build foundation, not depth.

Clarity
Clarity ≈ attention + signal + coherence + signal/coherence coupling

Clarity is perceptual distinction. It improves when observation becomes signal.

Integration
Integration ≈ orientation + witness + trace + stabilization + damping + trace memory

Integration is the global capacity to hold the system without collapse.

Depth
Depth = compressed(maturity × weighted(qBits + strata + manifest seed + late load))

Depth must grow slowly. Early orientation cannot masquerade as depth. Maturity gates the depth curve.

Strain
Strain ≈ entanglement + imbalance + accepted load not yet stabilized

Strain is not failure. It is load. It becomes dangerous only when it outruns integration.

Field Reading
Field Reading ≈ harmonic(clarity, integration, depth) - strain penalty + foundation support

Field Reading is 0-64. It rewards balance rather than raw accumulation.

Complexity
Complexity = compressed(depth + strain + manifest seed + entanglement + late-stage load)

Complexity is system load, not activity. Clicking does not equal complexity.

Manifest Seed
Manifest Seed = weighted(expressive qBits + expressive strata + milestones + trace memory + field reading)

Manifest Seed is expression, not power. It should remain below complexity early.

Mathematical ConstitutionNo depth without integration. No complexity without load. No manifestation without trace. No field reading without balance.

VIII. Calibration Overlay

manifest-calibration.js is a stabilization layer added after the engine became functionally correct but numerically too eager. It currently wraps NEODOXENT_STATE.get() so visible and downstream readings are calibrated before display.

Honest Architecture NoteThe calibration overlay is intentional technical debt. It is acceptable now because it prevents breaking the protected shell and avoids risky full-engine rewrites. Later, its math should be moved natively into state-engine.js.
Raw engine → calibration overlay → display state
S.rawGet() preserves the original engine state.
S.get() returns calibrated display state.

The overlay also prevents Manifest flicker by rewriting indexical output at the assignment layer. This was necessary because main.js still rendered raw Manifest while the calibrated system required Manifest Seed.

XIII. Dynamics Layer

The dynamics layer currently exists as a textual and mathematical reading inside the Field Resources panel. It derives local response from couplings, entanglement, imbalance, readiness, pressure, tension, and stability.

response mode = f(tension, readiness, pressure, stability)
readiness = coupling + stability - tension cost

DynamosDynamos is the planned graphical representation of the dynamics layer. It should not be built before this Mastorial defines the current dynamics. Dynamos should visualize response, pressure, strain, readiness, and coupling without adding new mechanics prematurely.

The present dynamics layer is affective in the limited sense that it responds to interaction patterns and changes guidance. It is not yet affective in the visual sense; Dynamos will become the visual affective instrument.

XV. Safety and Boundary Doctrine

The system is symbolic, interpretive, and self-directed. It should never present itself as diagnosis, therapy, prophecy, command authority, empirical proof, or external truth engine.

BoundaryThe interface can guide attention, structure pacing, and surface symbolic readings. The user remains responsible for interpretation, action, and meaning.

XVI. Known Technical Debt

Some redundancy is intentional. Some is technical debt. The following should be documented before future Codex use.

  • main.js still contains older cardTier() logic. Contextual card gating currently lives in interface-drawer.js.
  • manifest-calibration.js wraps state output and should eventually be absorbed into state-engine.js.
  • The render cycle still uses a one-second interval. It works, but a future event-driven render pass would be cleaner.
  • Some latent variables and couplings exist before they are visually surfaced. This is acceptable but must remain governed.
Debt RuleDo not refactor for beauty while the system is unstable. Refactor only after the Mastorial records what the system is meant to preserve.

XVII. Recovery Manual

If the site breaks, do not panic and do not add features during recovery. First determine whether the shell, script order, or local state is the issue.

1. Open recursion.html and check for placeholders.
2. Confirm it contains full style and full body.
3. Verify script order:
   state-engine.js
   modules.js
   main.js
   interface-drawer.js
   manifest-calibration.js
4. Hard refresh browser.
5. Reset local state.
6. If still broken, inspect console.
7. Restore last complete shell before adding any feature.
